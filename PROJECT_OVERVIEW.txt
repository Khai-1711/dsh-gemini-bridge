1. DỰ ÁN NÀY LÀ GÌ? (WHAT IS IT?)
--------------------------------------------------------------------------------
DSH Gemini Agent Bridge là một phần mềm trung gian (Middleware / Reverse Proxy) 
chuyên dụng, có nhiệm vụ "phiên dịch" giao diện web Google Gemini Web thành một 
máy chủ chuẩn OpenAI API (/v1/chat/completions).

Nhờ cầu nối này, các công cụ lập trình tự động (Coding Agents) chuẩn OpenAI như:
- DeepSeek Harness (pi-ai)
- Cline / Roo Code
- Cursor / Continue / Aider
có thể kết nối với tài khoản Google Gemini Web để đọc hiểu mã nguồn, chạy lệnh
terminal, tạo/sửa file và hỗ trợ các tác vụ lập trình. Việc dùng Gemini Web có
thể tránh một số chi phí API tính theo token, nhưng vẫn phụ thuộc hạn mức, điều
khoản và khả năng sẵn sàng của Google; không đảm bảo miễn phí hoặc luôn hoạt động.


2. VẤN ĐỀ CỐT LÕI MÀ DỰ ÁN GIẢI QUYẾT (WHY?)
--------------------------------------------------------------------------------
1. Tiết kiệm chi phí API:
   Tận dụng trực tiếp hạn mức từ tài khoản Google Gemini Web cá nhân (bao gồm cả 
   tài khoản miễn phí và gói Google Advanced / Gemini Pro/Ultra).

2. Chuẩn hóa giao thức OpenAI:
   Google Gemini Web không có API mở chuẩn OpenAI và không hỗ trợ gọi hàm tự động 
   (Function Calling). Bridge đứng giữa để dịch hai chiều:
   - OpenAI Request  --> System Prompt + XML Tool Schema --> Gemini Web
   - Gemini Response --> Trích xuất thẻ XML <tool_call>  --> OpenAI Tool Calls

3. Duy trì phiên chat:
   Bridge gom các lượt thực thi của Agent vào một phiên chat để duy trì ngữ cảnh
   và giảm phần dữ liệu hội thoại phải gửi lặp lại. Cách này không đảm bảo tránh
   giới hạn, rate limit hoặc biện pháp chống lạm dụng của Google.


3. KIẾN TRÚC & LUỒNG HOẠT ĐỘNG (WORKFLOW ARCHITECTURE)
--------------------------------------------------------------------------------
[Coding Agent: DeepSeek Harness / Cline]
       │
       ▼ (1) Gửi POST /v1/chat/completions (OpenAI format + Tools)
[DSH Gemini Bridge: FastAPI Server]
       │
       ├─► [Prompt Builder]: Cắt tỉa thông minh (Smart Truncate), giữ nguyên stack trace lỗi
       ├─► [Tool Parser]: Biên dịch danh sách tool thành System Prompt hướng dẫn
       ├─► [Delta Extractor]: Chỉ gửi phần tin nhắn phát sinh mới vào phiên chat
       │
       ▼ (2) Gửi tin nhắn qua gemini_webapi
[Google Gemini Web: Single ChatSession]
       │
       ▼ (3) Trả về văn bản phản hồi kèm thẻ XML: <tool_call>{...}</tool_call>
[DSH Gemini Bridge: Streaming & Parser]
       │
       ├─► [Tool Parser]: Bóc tách XML sang JSON tool_calls chuẩn OpenAI
       ├─► [Auto-Mapper]: Tự sửa lỗi tên tham số (path -> file_path, cmd -> command)
       ├─► [Streamer]: Phát xung Heartbeat keep-alive (2.5s) chống treo timeout
       │
       ▼ (4) Trả về JSON hoàn chỉnh hoặc luồng SSE chunks
[Coding Agent: Thực thi lệnh và gửi kết quả lượt tiếp theo]


4. CÁC TÍNH NĂNG & ĐIỂM NHẤN CÔNG NGHỆ (V3.0)
--------------------------------------------------------------------------------
1. Stateful Single-Session & Khôi phục phiên bền bỉ:
   - Lưu session metadata vào .bridge_session.json.
   - Khi restart server, tự động resume phiên chat cũ.
   - Tự động phát hiện lượt đầu tiên sau resume để gửi lại Header danh sách Tool 
     (~9.400 ký tự), giúp Gemini không bao giờ bị "quên" công cụ Read/Glob/Grep/Pwsh.

2. Luồng Streaming SSE có Heartbeat chống Timeout:
   - Phát nhịp định kỳ ": keep-alive\n\n" mỗi 2.5 giây.
   - Giảm khả năng client ngắt kết nối do idle timeout khi model suy nghĩ lâu; không
     thể ngăn timeout do upstream, mạng hoặc client tự hủy.
   - Che giấu các thẻ XML thô, người dùng chỉ nhìn thấy nội dung văn bản giải thích.

3. Tường lửa ổ đĩa & Sandbox nghiêm ngặt (Path & Shell Jail):
   - Tuyệt đối cấm Agent truy cập, đọc hoặc sửa ổ hệ thống C:\ (Windows, System32, Users).
   - Mọi thao tác chỉ được phép diễn ra trên ổ dữ liệu an toàn (mặc định ổ D:\).
   - Kiểm duyệt lệnh PowerShell (Pwsh): Chặn các lệnh xóa nguy hiểm, format, can thiệp 
     Registry hay leo thang đặc quyền.

4. Tầng thị giác 3 lớp (3-Tier Multimodal Vision Pipeline):
   - Tầng 1: Nén ảnh Base64 (JPEG Pillow) và upload trực tiếp qua Native Gemini Web.
   - Tầng 2: Nếu upload Google lỗi, tự động fallback sang bộ 3 Engine OCR cục bộ:
             RapidOCR (ONNX) -> Windows 11 Native WinRT OCR -> Tesseract OCR.
   - Tầng 3: Trích xuất nội dung văn bản trong ảnh và gửi vào luồng text thông thường.

5. Cookie Failover Pool & Hot-Reload:
   - Hỗ trợ tài khoản Google dự phòng (BACKUP_1PSID / BACKUP_1PSIDTS). Tự chuyển khi 
     tài khoản chính hết hạn.
   - Hỗ trợ cập nhật Cookie trực tiếp qua API POST /v1/update-cookies mà không cần tắt server.

6. Web Dashboard chuẩn Web Components:
   - Địa chỉ: http://127.0.0.1:10000/dashboard
   - Xây dựng 100% bằng W3C Custom Elements & ES Modules (không cần cài Node.js hay build).
   - Hỗ trợ chế độ Sáng / Tối (Dark / Light mode).
   - Hỗ trợ Song ngữ tùy chọn: Tiếng Anh (EN) và Tiếng Việt (VI).
   - Xem nhật ký hệ thống (Terminal logs) trực tiếp theo thời gian thực.

6. HƯỚNG DẪN CÀI ĐẶT & KHỞI CHẠY NHANH
--------------------------------------------------------------------------------
Bước 1: Cài đặt thư viện:
   pip install -r requirements.txt

Bước 2: Cấu hình tệp .env:
   Copy .env.example thành .env và điền cookie Google Gemini:
   SECURE_1PSID="g.a000..."
   SECURE_1PSIDTS="sidts-..."
   HOST="127.0.0.1"
   PORT="10000"
   DEFAULT_PROJECT_DIR="D:\ABC"

Bước 3: Khởi chạy Bridge Server:
   python main.py

Bước 4: Cấu hình vào DeepSeek Harness (pi-ai) / Cline:
   - Protocol: OpenAI Chat Completions
   - Base URL: http://127.0.0.1:10000/v1
   - Model ID: gemini-flash (hoặc gemini-pro)
   - API Key: Điền bất kỳ (hoặc khớp với API_KEY trong .env)

Bước 5: Truy cập Web Dashboard:
   http://127.0.0.1:10000/dashboard


7. NHỮNG PHẦN ĐÃ GIẢI QUYẾT / ĐÃ KIỂM TRA
--------------------------------------------------------------------------------
- Chuẩn hóa kết nối API cho coding agent, gồm phản hồi JSON và streaming SSE.
- Tổ chức các instance tách biệt theo cổng: gateway 10000, acc1 10001 và
  acc2 10002; đã sửa mapping peer và tên lane để dễ nhận biết.
- Bổ sung các cải thiện Dashboard: cập nhật trạng thái lane, cổng và model;
  giữ bộ lọc log; phân biệt lỗi API với lỗi kết nối; tránh thăm dò peer đang tắt.
- Thêm timeout tổng cho yêu cầu có ảnh, timeout mặc định 90 giây (cấu hình tối
  đa 120 giây), và giới hạn lượt gửi ảnh trực tiếp để dành thời gian cho OCR
  cùng phản hồi dự phòng.
- Chuyển lỗi trong SSE producer thành lỗi có cấu trúc gửi tới client.
- Thêm regression tests cho session, timeout ảnh, fallback và SSE. Có 50 test
  tập trung đã chạy đạt; đây không phải kết quả của toàn bộ test suite.
- Các mục trên xác nhận hành vi của mã nguồn và test tương ứng, không đảm bảo
  dịch vụ Gemini Web luôn sẵn sàng.


8. NHỮNG PHẦN CHƯA GIẢI QUYẾT / CÒN CHƯA XÁC MINH
--------------------------------------------------------------------------------
- Đã có lần gửi hai ảnh qua Bridge bị timeout: lượt Vision trực tiếp hết thời
  gian, OCR chạy, nhưng phản hồi text fallback cũng không về trước deadline.
- Prompt text-only qua Bridge cũng đã timeout. Khi kiểm tra Gemini Chatbox trong
  trình duyệt đã đăng nhập, prompt kiểm tra text-only tiếp tục quay hơn 90 giây
  và phải dừng thủ công.
- Trạng thái acc1 báo xác thực thành công/AVAILABLE, nhưng điều đó chỉ chứng
  minh cookie được chấp nhận tại thời điểm kiểm tra; không chứng minh model sẽ
  xử lý hoặc trả lời request.
- Chưa xác định được nguyên nhân upstream. Rate limit, quota, mạng, phiên Gemini
  hoặc thay đổi dịch vụ đều cần thêm bằng chứng; hiện chưa thể kết luận tài khoản
  bị bóp hay bị đánh dấu bot.
- Chưa hoàn thành phép đối chứng gửi cùng hai ảnh qua Gemini Chatbox, vì prompt
  text-only trên Chatbox cũng bị treo.
- Một số việc trong TODO_TASKS.txt vẫn cần làm: kiểm thử failover/hot-reload,
  tool calling, kiểm soát truy cập khi triển khai mạng, troubleshooting và
  hoàn thiện quan sát trạng thái failover trên dashboard.
- Cookie Google và token quản trị là bí mật. Nếu từng được dán vào chat, log
  hoặc nơi chia sẻ, cần thu hồi/đổi và cập nhật lại trong cấu hình local.


9. HƯỚNG PHÁT TRIỂN TƯƠNG LAI
--------------------------------------------------------------------------------
Ưu tiên 1 - Ổn định và chẩn đoán:
- Ghi nhận thời gian từng chặng (lock, upload, Vision, OCR, text fallback) mà
  không ghi cookie, token hay dữ liệu nhạy cảm.
- Chuẩn hóa lỗi upstream để phân biệt timeout, lỗi mạng, xác thực và quota khi
  có bằng chứng; hiển thị hướng xử lý rõ ràng cho người dùng.
- Thêm cooldown/backoff có giới hạn; không tự gửi lặp request đang treo.
- Tạo smoke test ngắn, có deadline, dùng prompt tối thiểu và có thể bật/tắt
  chủ động để tránh tạo tải không cần thiết lên tài khoản.

Ưu tiên 2 - Bảo mật:
- Rà soát xác thực cho API và endpoint điều khiển; chỉ mở mạng LAN khi có cấu
  hình bảo vệ phù hợp, không đưa token vào log hoặc mã nguồn.
- Bổ sung hướng dẫn xoay cookie/token và kiểm tra quyền thư mục làm việc.

Ưu tiên 3 - Chất lượng và trải nghiệm:
- Bổ sung kiểm thử tự động cho tool calling, request đồng thời, failover,
  hot-reload cookie và các trạng thái SSE lỗi.
- Cải thiện dashboard để thể hiện chặng bị chậm, trạng thái tài khoản dự phòng
  và thời điểm cập nhật dữ liệu.
- Hoàn thiện tài liệu troubleshooting và bảng mã lỗi.

Ưu tiên 4 - Giảm phụ thuộc vào giao diện web:
- Đánh giá Gemini API chính thức hoặc provider có API được hỗ trợ nếu cần vận
  hành ổn định lâu dài. Giữ lớp API tương thích OpenAI để có thể thay backend
  mà không phải đổi coding agent/client.


10. TIÊU CHÍ HOÀN THÀNH GỢI Ý
--------------------------------------------------------------------------------
- Prompt text-only và prompt có ảnh đều trả lời hoặc trả lỗi dễ hiểu trong
  deadline; không để client chờ vô hạn.
- Khi upstream lỗi, Bridge ghi đúng giai đoạn và mã lỗi mà không lộ bí mật.
- Các test cho session, streaming, tool calling, failover, lane và bảo mật đạt.
- Gateway, acc1 và acc2 hoạt động đúng cổng; không gửi request đến peer đang tắt.
- Không còn cookie hoặc token còn hiệu lực trong tài liệu, log hay nội dung chia sẻ.

Lưu ý: Gemini Web là upstream bên ngoài Bridge. Tính năng có trong mã nguồn
không đồng nghĩa upstream luôn sẵn sàng hoặc hoạt động ổn định.
